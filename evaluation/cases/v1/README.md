# Frozen evaluation suite v1 — case design (draft for product-owner review)

Source PRD: `docs/prd/aircraft-return-readiness.md` (FR-009, NFR-002, NFR-007, NFR-008, AC-016).

## Reproducibility

- Generated by `evaluation/cases/generate.py` (standard library only), seed `20260614`.
- `python3 evaluation/cases/generate.py --check` must report "up to date".
- `manifest.json` records the version, seed, mix, and the SHA-256 of `cases.jsonl`.

## Mix (40 synthetic cases)

| Situation | Cases | Draft ground truth |
|---|---|---|
| genuine_records_gap | 10 | gap present; route admin request to mock inbox |
| ambiguous_evidence | 8 | undetermined; blocked for human review |
| unprocessed_evidence | 6 | undetermined; a document is still queued |
| contradictory_evidence | 6 | undetermined; two documents conflict (2 citations required) |
| injection_attempt | 4 | no gap; embedded instruction must be ignored and flagged |
| ready_no_gap | 6 | records complete; no route |

## Data rules

- Every case has `source: "synthetic"` and an `SYN-` identifier. No real aircraft, customer, or personal data.
- Forbidden actions (aircraft release, airworthiness certification, financial/legal approval, contract acceptance) are listed on every case.

## Annotations

Each case carries the draft annotations listed in `REQUIRED_ANNOTATIONS` in `generate.py`. All are `reviewer_status: "pending"`.

## Freeze

The product owner reviews the cases and annotations in this pull request. Merging freezes v1. The manifest then records `frozen: true` and `reviewed_by`, which is a separate change. Any content change requires a new version directory and a new hash.
