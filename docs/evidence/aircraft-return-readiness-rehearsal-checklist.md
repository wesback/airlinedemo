# Aircraft return-readiness rehearsal capture

This checklist prepares the AC-012 run and AC-019 evidence for DD-038. Only the product owner's actual rehearsal on a frozen revision passes; this checklist and schema are not evidence. Scripts do not deploy, invoke a model, create a trace, infer outcomes or fill evidence fields.

1. Check out the frozen repository revision and deploy its matching fixture configuration. Record revision, configuration version, deployment ID and application build; use synthetic data only.
2. In an approved evidence directory free of secrets, credentials, connection strings and customer records, set `REHEARSAL_TIMING_OUTPUT` to a new path and run `docs/evidence/scripts/aircraft-return-readiness-timing.sh`. Press Enter only when the rehearsal starts, the first-screen outcome appears, the live segment starts and it ends. The file records UTC boundaries and monotonic durations. A limit breach records `fallbackOutcome: used`, not live success.
3. Perform the AC-012 journey and record the actual decision and each journey state. If fallback is used, record its fixture ID and application version; never claim a fallback as a live outcome.
4. From the same signed-in session, set `REHEARSAL_BASE_URL`, `REHEARSAL_SESSION_COOKIE`, `REHEARSAL_CASE_ID`, `REHEARSAL_RUN_ID`, `REHEARSAL_INVESTIGATION_ID` and a new `REHEARSAL_TRACE_OUTPUT` path. Run `docs/evidence/scripts/aircraft-return-readiness-trace-capture.sh`; it saves only the stored, ordered dashboard trace response. An unavailable endpoint, denied scope or absent trace leaves no capture file.
5. Complete `aircraft-return-readiness-rehearsal-template.json` with the actual versions, deployment, timestamp, durations, real 30-second trace reference, simulated decision, fallback details and accessibility result; keep identifiers consistent with the run.
6. Attach the completed record and captures for review. The product owner verifies and attests to the actual frozen-revision run. A template, checklist or capture from another revision does not pass. The trace command requires an existing session cookie and exact case/run/investigation IDs; it never calls `az` or `gh`.
